# Codex Pantheon v0.8.1 — GPT-6 model refresh

v0.8.1 moves Pantheon's supported Sol and Luna roles onto the GPT-6 generation while preserving the v0.8 orchestration architecture and ownership boundaries.

## Architecture

The selected Codex main-thread model remains the Orchestrator:

- **GPT-6 Astra or GPT-6 Sol** — planning, architecture, tradeoffs, sequencing, delegation, reconciliation, final review, verification judgment, and user communication. The Orchestrator never implements repository changes.
- **`luna_explorer` / GPT-6 Luna High** — read-only repository reconnaissance and evidence.
- **`luna_librarian` / GPT-6 Luna High** — read-only authoritative external/reference research.
- **`luna_fixer` / GPT-6 Luna Max** — bounded implementation of the Orchestrator's specification and assigned focused validation.

The ownership rule is unchanged:

> **Orchestrator decides. Luna specialists execute their lane.**

Pantheon still does not install or spawn a second Astra/Sol Orchestrator, maintain a parallel model selector, or allow the Orchestrator to fall back to direct implementation.

## Why Fixer uses Max

GPT-6 Luna is substantially stronger on software-engineering work at higher reasoning effort. Pantheon therefore uses Max only where it buys the most value: the write-enabled Fixer lane. Explorer and Librarian remain on High to keep evidence gathering fast and quota-conscious.

This is a role-specific effort change, not a new routing mode:

- Explorer: High
- Librarian: High
- Fixer: Max

## Live verification

`pantheon verify` continues to exercise one real `luna_explorer` child because the verifier is intended to prove role selection, V2 control-plane behavior, model resolution, round-trip completion, and `fork_turns: "none"` isolation with minimal live usage.

The verifier now requires runtime evidence for **GPT-6 Luna High**. It does not exercise Fixer/Max and therefore does not consume an implementation-grade Max child turn.

## Unchanged orchestration semantics

v0.8.1 does not change:

- solo-by-default behavior;
- explicit, thread-scoped Pantheon activation;
- GPT-6 Astra/Sol ownership of planning, architecture, tradeoffs, scheduling, reconciliation, review, and final verification;
- Explorer/Librarian read-only boundaries;
- Fixer-only repository implementation;
- native MultiAgent V2 `spawn_agent`;
- explicit configured `agent_type`;
- `fork_turns: "none"`;
- hard dependency barriers;
- structured evidence and implementation receipts;
- shortest-safe-flow dispatch;
- delta-only correction loops;
- Daily sequential behavior;
- Full Pantheon dependency-safe parallelism;
- conservative same-assignment worker continuity.

## Upgrade

macOS/Linux:

```bash
./pantheon bootstrap
```

Windows PowerShell:

```powershell
.\pantheon.ps1 bootstrap
```

Bootstrap refreshes the three Luna role files, four Pantheon skills, managed policy block, lifecycle payload, and installed version marker, then runs static Doctor validation.

## Verification

Static validation:

```bash
./pantheon doctor
```

Opt-in live runtime verification:

```bash
./pantheon verify
```

or on Windows:

```powershell
.\pantheon.ps1 verify
```

The GPT-6 Sol/Luna availability and API identifiers are documented by OpenAI at https://openai.com/index/introducing-gpt-6-sol-and-luna/.
