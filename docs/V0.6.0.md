# Codex Pantheon v0.6.0 — Astra Orchestrator, Luna specialists, and native Windows support

v0.6.0 is the first GitHub release after v0.5.0. It replaces the generic v0.5 `pantheon_worker` with a Codex-native adaptation of the core `oh-my-opencode-slim` Orchestrator → Explorer/Librarian/Fixer workflow, makes Luna lanes glanceable in Codex task surfaces, and adds a native PowerShell lifecycle frontend for Windows.

## Architecture

- **GPT-6 Astra** remains the main Codex thread and acts as the Orchestrator.
- **`luna_explorer` / GPT-5.6 Luna High** is hard read-only repository reconnaissance.
- **`luna_librarian` / GPT-5.6 Luna High** is hard read-only docs/API/upstream/reference research.
- **`luna_fixer` / GPT-5.6 Luna High** is workspace-write bounded implementation of Astra's specification.

Astra owns the implementation plan, architecture, product/tradeoff decisions, prioritization, integration, review, final verification judgment, merge/release verdicts, and final communication.

## Canonical routing

When no research is needed:

```text
Astra plan/specification → Luna Fixer → Astra review/verification
```

When evidence is needed:

```text
Luna Explorer and/or Librarian → Astra synthesizes evidence → Astra plan/specification → Luna Fixer → Astra review/verification
```

Explorer/Librarian never create the solution plan. Fixer does not independently replan the mission. Astra does not use a research pass and then take over substantive implementation merely because the implementation became obvious.

## Glanceable Luna task identity

Pantheon now requires role-prefixed child task names so running work is identifiable without inferring the subagent from a generic task title. The native Codex-compatible convention is:

```text
luna_explorer_<specific_assignment>
luna_librarian_<specific_assignment>
luna_fixer_<specific_assignment>
```

Astra remains the main thread and is not spawned merely to create a child card.

## Pantheon Daily

Daily retains the same ownership model with more conservative delegation and no parallel child calls. The v0.5 numeric `0-1` worker-call rule is removed. Sequential evidence → Astra plan → Fixer is explicitly allowed when required.

## Full Pantheon

Full Pantheon uses the same ownership model and may parallelize genuinely independent read-only evidence lanes or non-overlapping Fixer workstreams.

## Native Windows support

Pantheon now exposes platform-native lifecycle frontends over one shared payload:

- **macOS/Linux:** `pantheon` and `install.sh` via Bash.
- **Windows:** `pantheon.ps1` and `install.ps1` via PowerShell.

Windows does not require WSL or Git Bash for Pantheon installation. The PowerShell frontend supports Windows PowerShell 5.1 and newer PowerShell runtimes, uses `%USERPROFILE%\.codex` and `%USERPROFILE%\.agents\skills` by default, honors the same `CODEX_HOME` and `PANTHEON_SKILLS_HOME` overrides, and installs the same three Luna agents, four skills, managed `AGENTS.md` block, and version marker as the Bash frontend.

Windows Doctor checks PATH plus current native Codex standalone/Desktop runtime layouts under `%LOCALAPPDATA%`. Protected-path handling treats NTFS reparse points as the Windows analogue of Pantheon's Bash symlink safeguard.

## Upgrade / install

macOS or Linux:

```bash
./pantheon bootstrap
```

Windows PowerShell:

```powershell
.\pantheon.ps1 bootstrap
```

Bootstrap installs or updates Pantheon-owned files and runs `doctor`. It does not activate Pantheon mode.

## Migration from v0.5

Bootstrap/update:

- removes the v0.5 `pantheon-worker.toml`;
- installs `luna-explorer.toml`, `luna-librarian.toml`, and `luna-fixer.toml`;
- continues removing the old v0.4 Pantheon specialist filenames and `pantheon-team` skill;
- refreshes the four skills and managed `AGENTS.md` block;
- preserves unrelated user-owned Codex agents, skills, and configuration.

## Validation

The v0.6.0 package is covered by the Linux/Bash and Windows/PowerShell lifecycle suites in GitHub Actions. The suites exercise install, update, doctor, bootstrap, migration cleanup, path defaults, preservation of user-owned configuration, malformed-marker fail-closed behavior, and uninstall. The current release candidate also includes the Windows PowerShell 5.1 parser compatibility fix.

Repository tests prove packaged policy/configuration and lifecycle behavior. Live model/provider availability and native child-agent behavior remain runtime concerns and are not implied by static package tests.

## Upstream adaptation

The role/routing semantics are adapted from the MIT-licensed [`oh-my-opencode-slim`](https://github.com/alvinunreal/oh-my-opencode-slim) project. Pantheon does not port its OpenCode SDK, Bun runtime, TUI, job board, wake scheduler, or other OpenCode-specific machinery. See `THIRD_PARTY_NOTICES.md`.

## Not included

No automatic activation, prompt interception, persistent mission state, quota meter, scheduler, daemon, custom agent runtime, Oracle/Designer/Reviewer/Verifier roster, separate team mode, or fast/normal/deep effort layer.
