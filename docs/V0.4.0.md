# Codex Pantheon v0.4.0 — Daily Mode

Pantheon v0.4 adds a quota-conscious operating profile for day-to-day Codex work without weakening full Pantheon or adding any runtime/token-accounting machinery.

## Goal

`$pantheon-daily` is for users who want specialist delegation available throughout normal work while stretching a fixed Codex allowance across a longer period. It optimizes for useful specialization per child-agent call rather than maximum fan-out.

Full `$pantheon` remains the quality-and-confidence-first profile for work where additional independent reasoning, research, review, verification, or parallelism is worth the extra usage.

## Operating profiles

| Profile | Activation | Primary objective | Dispatch posture |
| --- | --- | --- | --- |
| Ordinary Codex | default | Lowest orchestration overhead | Parent only |
| Pantheon Daily | `$pantheon-daily` | Quota-conscious day-to-day orchestration | Parent first; normally 0-2 specialist calls |
| Full Pantheon | `$pantheon` | Quality/confidence and useful parallelism | Progressive, evidence-earned delegation without Daily's numeric ceiling |

Daily and full Pantheon are mutually exclusive sticky profiles within one thread. Invoking the other profile switches the thread. `stop using Pantheon` returns the thread to ordinary Codex behavior. Activation never persists across threads.

The existing `$pantheon-plan`, `$pantheon-review`, and `$pantheon-team` workflows remain request-scoped and do not replace the current sticky profile.

## Daily routing contract

Pantheon Daily:

- allows zero specialists when the parent can complete the work efficiently;
- chooses one best-fit specialist first when delegation materially reduces uncertainty, rework, or parent effort;
- normally uses no more than two specialist calls for one user request;
- permits a third specialist call only for a concrete unresolved blocker, risk, or evidence gap that the parent cannot resolve efficiently;
- never uses four or more specialist calls for one Daily request;
- never silently switches into full Pantheon or team mode;
- prefers Explorer or Librarian rather than both unless repository and external-reference evidence are independently necessary;
- prefers at most one independent implementation check—Reviewer or Verifier—based on the dominant risk;
- does not default to Fixer → Reviewer → Verifier.

The parent can implement low-risk, well-scoped work directly in Daily. Fixer is reserved for delegated implementation that materially saves work or cleanly isolates a substantial change.

## Context and agent definitions

Daily reuses the existing seven Pantheon agents unchanged. It does not add a cheaper duplicate roster or change their pinned models/reasoning levels.

All Daily child spawns use the same v0.3 context-efficiency contract: `fork_turns: "none"` by default, self-contained bounded assignments, minimum justified inheritance, no recursive subagents, delta-only handoffs, and evidence-based stopping.

## Switching semantics

- Inactive → `$pantheon-daily`: enter Daily.
- Inactive → `$pantheon`: enter full Pantheon at normal effort unless another effort is requested.
- Daily → `$pantheon`: enter full Pantheon at normal effort unless another effort is requested.
- Full Pantheon → `$pantheon-daily`: enter Daily and clear full-Pantheon effort.
- Either profile → `stop using Pantheon`: return to ordinary Codex and clear full-Pantheon effort.

Fast/normal/deep remain full-Pantheon effort levels. Daily is a separate operating profile, not a new effort level.

## What v0.4 does not add

- No token accounting or billing estimation.
- No rate-limit or quota polling.
- No persistent daily/weekly budget database.
- No automatic profile switching based on remaining usage.
- No daemon, scheduler, HUD, custom orchestration runtime, or new agent role.

Repository tests verify packaged policy/configuration and lifecycle behavior. They do not prove live Codex quota consumption, billing behavior, provider availability, or native child-spawn execution.
