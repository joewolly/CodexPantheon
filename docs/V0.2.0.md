# Codex Pantheon v0.2.0 — Coordination & Reliability

v0.2 keeps Pantheon intentionally slim while formalizing the pieces that make native Codex delegation reliable and predictable.

## Added

- Shared bounded child-agent contract across all seven Pantheon roles.
- Explicit workflow skills:
  - `$pantheon`
  - `$pantheon-plan`
  - `$pantheon-review`
  - `$pantheon-team`
- Fast / normal / deep orchestration-depth semantics without duplicate agent profiles.
- Minimal fan-out and anti-over-orchestration policy.
- Independent Reviewer and Verifier responsibilities.
- Pantheon-managed block in `~/.codex/AGENTS.md`.
- Idempotent `install`, `update`, `doctor`, and `uninstall` commands.
- Regular-file agent installation; Pantheon does not use symlinked custom-agent TOMLs.
- Static installation drift checks in `doctor`.
- Installer regression tests covering preservation, idempotency, symlink replacement, marker corruption, drift detection, and uninstall safety.

## Intentionally not added

- Automatic Pantheon activation.
- Prompt interception or keyword routing.
- Background daemons.
- Persistent mission/task databases.
- Recursive child-agent spawning.
- tmux/worktree orchestration.
- HUDs, dashboards, token accounting, or rate-limit management.
- Large specialist catalogs.
- Custom orchestration servers.

## Upgrade note from v0.1

The v0.2 installer safely owns only the `<!-- PANTHEON:START -->` / `<!-- PANTHEON:END -->` block it creates. If a v0.1 installation previously placed Pantheon instructions in `~/.codex/AGENTS.md` without managed markers, v0.2 will not delete that user-owned text automatically. `pantheon doctor` warns when Pantheon-like text remains outside the managed block so it can be reviewed manually.

## Codex-assisted bootstrap

Opening the Pantheon source directory in Codex and asking it to install/update Pantheon now has a defined repository-level behavior. Codex runs `./pantheon bootstrap`, which synchronizes only Pantheon-owned state and then runs `doctor`. Safeguard failures remain fail-closed and must not be bypassed with manual overwrites.
