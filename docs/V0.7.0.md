# Codex Pantheon v0.7.0 candidate — Dual Orchestrator + context efficiency

The v0.7.0 candidate makes the Pantheon Orchestrator interchangeable between **GPT-6 Astra** and **GPT-5.6 Sol** without adding a second Orchestrator, duplicate skill set, or model-routing runtime.

## Architecture

The selected supported Codex main-thread model is the Orchestrator:

- **GPT-6 Astra or GPT-5.6 Sol** — planning, architecture, product/tradeoff decisions, prioritization, delegation, integration, review, final verification, and user communication.
- **`luna_explorer` / GPT-5.6 Luna High** — hard read-only repository evidence.
- **`luna_librarian` / GPT-5.6 Luna High** — hard read-only authoritative external/reference evidence.
- **`luna_fixer` / GPT-5.6 Luna High** — bounded implementation of the Orchestrator's specification.

Canonical dependency:

```text
Explorer/Librarian evidence when needed
                ↓
     Orchestrator plan/specification
                ↓
          Luna Fixer implements
                ↓
     Orchestrator reviews/verifies
```

## Model selection

Pantheon does not maintain a second model selector. Select Astra or Sol using Codex's native model control, then invoke `$pantheon` or `$pantheon-daily`.

This design avoids:

- a second model hop;
- duplicated Orchestrator prompts;
- persistent selector state;
- disagreement between Pantheon configuration and the model Codex is actually running;
- separate Astra/Sol skills that could drift over time.

Changing between Astra and Sol does not require reinstalling Pantheon because the installed routing contract is model-neutral.

## Prompt/context optimization

v0.7.0 also tightens the hot-path instruction payload:

- Replaced Astra-specific ownership wording with one Orchestrator role contract.
- Compacted Explorer, Librarian, and Fixer developer instructions while preserving hard boundaries.
- Explicitly asks evidence lanes for the **minimum sufficient evidence**.
- Preserves native `fork_turns: "none"` as the default child context policy.
- Requires only the minimum self-contained assignment context needed to execute a bounded child task.
- Preserves role-prefixed child task names for glanceable Codex surfaces.
- Adds no extra agent, scheduler, state store, quota meter, or custom orchestration runtime.

Luna stays on GPT-5.6 Luna High in this release. Worker-effort tuning is intentionally not mixed into the dual-Orchestrator change, making Astra-versus-Sol behavior easier to evaluate independently.

## Profiles

- **Daily:** same ownership, conservative delegation, sequential children only, no numeric call ceiling.
- **Full:** same ownership, justified parallel read-only evidence and non-overlapping Fixer workstreams allowed.
- **Plan/Review:** request-scoped and owned by the current main-thread Orchestrator.

## Upgrade

Run the platform bootstrap command:

```bash
./pantheon bootstrap
```

or:

```powershell
.\pantheon.ps1 bootstrap
```

The v0.7.0 release cut will refresh the three Luna definitions, four skills, managed policy block, and version marker. Existing v0.4/v0.5 cleanup and user-owned configuration safeguards remain unchanged.

## Validation boundary

Repository tests cover static package alignment, context/routing invariants, lifecycle installation/update/doctor/uninstall behavior, migration cleanup, and both platform frontends. Live Astra/Sol availability and native child spawning remain Codex runtime concerns.
